# Converter review, October 2026

Reviewed on 2026-10-15 before publication. Scope: the standalone converter,
its public library and CLI, privacy filtering, receipts, segmentation, hostile
archives and distribution contents. All work and verification were offline.
No real aircraft data, archive downloads or deployment actions were used.

## Findings and fixes

1. **High: operator classification survived broken continuity.** An inherited
   callsign could admit disconnected observations or a new takeoff after landing.
   Inheritance now applies only to the already-open movement, with matching
   aircraft metadata, a plausible connecting observation and the 48-hour bound.
   Every new movement uses current positive classification. Regressions cover
   excessive gaps, excessive speed, landing followed by another takeoff, and
   expiry of an unresolved movement. Explicit callsign clears now fail closed,
   and a later operator callsign cannot classify earlier unknown movements.

2. **High: registration opt-outs could be bypassed by missing or changed data.**
   A later snapshot could lose its registration and regain military/operator
   eligibility. Registration denials now remain attached to the observed hex
   in bounded RAM throughout a consecutive run. Missing registration fails
   closed when registration deny rules exist. Public classification normalises
   deny comparisons and rejects malformed ICAO identities. Tests cover missing,
   changed and differently cased identifiers. Hex keys are needed for known
   aliases whose registration history is unavailable after a cold start.

3. **Medium: receipt fields allowed unintended payloads (R1).** Arbitrary
   rejection strings and non-string quality rule versions could enter diagnostic
   or quality receipts. Rejection codes now use a closed vocabulary and versions
   must be bounded version strings. Whole-input fingerprints were removed from
   summaries; transfer digest verification remains available without emitting
   digests. Receipt-schema tests check aggregate counters, versions, dates and
   fixed status fields. Sentinel tests check records, aggregate keys, receipts,
   captured logs, stdout, stderr and formatted exception text. Private trace and
   point objects also omit their fields from default representations.

4. **Medium: zero-duration segments were emitted (R6).** A single airborne
   observation could produce a row with equal start/end timestamps, including
   after a confirmed landing or discontinuity. Every emitted segment now requires
   `t1 > t0`, including open fragments. Observed anonymous airport events remain
   available. Tests cover isolated reports, closed one-report movements and
   discontinuities. Existing fixtures now use multiple airborne observations
   where they assert a flight.

5. **Medium: distance could include an unknown-altitude observation.** The next
   airborne point could add a step from an observation whose airborne state was
   unknown. Distance now requires both observations to be airborne. A regression
   verifies that only the subsequent observed airborne step contributes.

6. **High: incomplete resource bounds for hostile archives.** Skipped auxiliary
   members, archive padding, JSON container allocation and retained boundary/group
   state could exceed practical limits. Header checks now reject oversized skipped
   members before body reads. Archive bytes, padding, retained tracks, anonymous
   groups and remembered registration denials have explicit ceilings. JSON depth
   and structure are checked before object allocation; wide encodings cannot
   bypass this check. CLI configurations are bounded and reject duplicate keys.
   Regressions exercise oversized headers, excessive padding, total byte limits,
   compressed expansion, deep/wide JSON, encoding bypasses and state exhaustion.

7. **Medium: malformed deflate and source errors escaped sanitisation.** Some
   gzip failures raised an uncaught decompressor exception, and library source
   errors could retain private filenames or bodies. Deflate failures now use
   `trace_encoding`; source read failures expose fixed `input_read` text. Invalid
   library dates clear continuity and use a fixed rejection. Tests cover library
   exception text and CLI rejection without traceback or partial stdout, plus
   malformed and oversized configurations.

8. **Publication defect: missing public method document.** README and source
   manifest entries pointed at a nonexistent document. They now reference the
   [public method](method.md); the source manifest includes this review and
   excludes hidden Markdown reference material. Public documentation link checks
   prevent recurrence. Reference-only material was deleted before building.

9. **High: a late contradictory duplicate could expose an earlier candidate.**
   The library emitted eligible candidates before reaching a conflicting member
   for the same identity, which might carry a privacy denial. Candidates now stay
   in a bounded 128 MiB RAM buffer until the entire archive passes validation.
   Neither the callback nor the CLI spool receives those candidates on failure.
   Regressions check a late military/PIA duplicate and candidate-buffer exhaustion,
   including aggregate diagnostics and captured output. Raw traces remain RAM-only.

## Required behavior checked

Privacy exclusions override both military and reviewed operator eligibility.
All combinations of the defined flag bits, non-ICAO identities, opt-outs,
unclassified aircraft and unknown/malformed flags are covered with synthetic
sentinels. Excluded identities contribute anonymous counts only. No operator,
aircraft identifier or trace-derived fingerprint belongs in diagnostics or
quality receipts. Raw bodies are never extracted or spooled.

Segmentation retains the specified thresholds: at least two explicit ground
reports separated by at least 30 seconds; adjacent gaps at most 30 minutes;
observed speed at most 1,000 knots; unresolved movements bounded to 48 hours.
Boundary tests check inclusive thresholds, overnight continuity, open fragments,
stale positions and observed airport transitions. No inferred endpoint adds an
airport movement. All emitted segments have strictly positive observed duration.

Tar traversal, links, devices, sparse/extension records, bad checksums, truncated
archives, conflicting duplicates, wrong dates, gzip corruption and trailing
nonzero bytes reject the generation. Reads and converter-owned collections have
explicit limits documented in the [method](method.md). Limit failures clear
continuity. The CLI stages sanitised output privately and publishes it only
after archive validation; named outputs retain their old contents on failure.

## Verification and limits

Verified with Python 3.12.3, pytest 9.1.1, Ruff 0.16.10, setuptools 68.1.2 and
wheel 0.42.0:

- `python -m pytest -q`: **222 passed**.
- `ruff check flights_converter tests`: passed.
- `ruff format --check flights_converter tests`: passed.
- `python -m pip wheel --no-index --no-deps --no-build-isolation --wheel-dir dist .`:
  built `flights_converter-0.1.0-py3-none-any.whl` offline.
- The same **222 tests passed** against an isolated installation of the wheel,
  from outside the checkout, including subprocess CLI tests.
- Distribution inspection verified all 17 wheel files against the package and
  expected metadata, and all 36 source-distribution files against public sources
  and expected generated metadata. Public documentation is included in the
  source distribution; reference material is absent.

Wheel SHA256: `c632a64b81fa895dd3b641bcef9fdcc2485b3bdb6084f1c83a03b9a831889fb2`.
Dependency resolution and build isolation were disabled; existing local build
tools supplied the backend. No network access was used.

Tests use synthetic, producer-shaped inputs. They establish neither real-release
throughput nor a measured peak-memory budget. Reviewed operator/airport
configuration and the output callback are trusted inputs. The library callback
receives staged candidates: the caller must discard the complete generation on
failure, enforce quality/coverage checks, apply requested retractions and replay
changed inputs transactionally. Earlier published rows and aliases require
caller-owned opt-out retraction. No publication or deployment was performed.
